## Decisions

- **Decision F** (asked at the start of M2): the read side and the seed script
  are built now so the pages show real D1 data. M3 adds the write side.
- **404 for a missing product or post**: the page returns an empty
  `404` response and Astro renders `404.astro`. `Astro.rewrite("/404")` is not
  allowed from an on-demand page to a prerendered one.
- **`build.format: "file"`**: with the default format, prerendered pages are
  `kontakt/index.html` and Cloudflare answers `/kontakt` with a 307 redirect to
  `/kontakt/`. As `kontakt.html` they are served at `/kontakt` directly.
  Verified with `astro preview`.
- **Published news** means `publishedAt IS NOT NULL`. The query returns its own
  model (`PublishedNewsPost`, `publishedAt: string`) so no `!` is needed.
- **Prices in the seed are 0** and show as 0,00 €. Real prices are entered in
  the admin; the seed is for local development only.
- **Slovenian number format**: CLDR groups thousands in Slovenian only from
  five digits on, so 1234,56 € has no dot and 12.345,67 € has one. My first
  test expected `1.234,56 €`; the test was wrong, not the code, and now checks
  both cases.
- **Images**: product, news and gallery photos are rendered from `/media/[id]`,
  which comes with uploads in M5. Until then products show their illustration,
  news posts show text only, and the gallery shows its empty state. The
  gallery list markup is in place, but it can only be checked with real
  uploads (M5).
- `galleryService.listGallery()` only passes the repository result on. It
  exists because pages call services, never repositories.
- Media query breakpoints (`48rem`, `56rem`, `60rem`) are written in the
  components: CSS custom properties cannot be used inside `@media`.
- The cow emblem is the final logo (checkpoint M1); the other two emblems were
  removed.
