## Decisions

Added to plan section 8:

- **Order status**: new becomes delivered or cancelled; delivered can go back
  to new ("Vrni med nova"). Cancelled is final, because its stock may already
  be sold again.
- **Cancel and delete** (order, news post, gallery photo) need a ticked
  checkbox in the same form. No JavaScript dialog.
- **Quantities** can change only while an order is new. A higher quantity
  must fit the stock (other orders, not counting the line itself); a lower one
  always fits, even below a lowered limit. Lines that do not fit keep their
  quantity and the other changes are saved, with a message. Quantity 0
  removes a line, but not the last one. The total is recalculated in the
  same batch. Adding a product to an existing order is not possible (the
  plan only asks for quantities).
- **Image type** comes from the file's first bytes (JPEG `FF D8 FF`, WebP
  `RIFF....WEBP`); the browser's claim is ignored.
- **Photos on pages**: product photos fill the 4:5 frame, news photos a 3:2
  frame (both cropped, so their size attributes only reserve that shape);
  gallery photos keep their shape. The gallery caption is required and is the
  alt text. News photos have empty alt text (the title is right above).

Other:

- **Replacing a photo**: the new image is stored, the record points to it,
  then the old image is deleted. Not one batch, so all image bytes stay inside
  `imageRepository` (the R2/KV swap point). If a step fails, the worst case is
  an unused image row.
- **Upload without JavaScript**: the file arrives without the measured size
  and is refused with "Fotografija mora biti WebP ali JPEG, največ 1600 px in
  500 KB. Za pripravo fotografije potrebuje stran JavaScript." The hint under
  the field says so too until the script replaces it.
- **Order list** starts with the open round, else the newest; the filter is a
  plain GET form (`?krog=&stanje=`).
